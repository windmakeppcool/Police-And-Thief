# 口袋巡逻队 · UI 设计方案

## 交付范围

本次仅交付设计方案和 HTML 视觉效果稿，不开发游戏玩法、平台接口、账号、存档或自动化测试，不修改现有 Cocos 工程。

- 预览入口：`design/pocket-patrol.html`
- 配套样式：`design/pocket-patrol.css`
- 用浏览器打开 HTML 即可查看；使用“界面预览”选择器切换全部页面。
- 按钮仅用于页面跳转、弹层和视觉状态演示。棋盘、关卡进度、分数均为示例数据。
- 卡通主视觉使用在线生成图片，需要联网加载；无框架与在线字体依赖。

## 一、视觉方向

**主题：薄荷色积木小镇。** 将“警察抓小偷”处理成轻松可爱的空间益智游戏，以圆润积木、卡通警徽和微缩街区建立辨识度，避免追捕题材的紧张感。

主菜单采用一个居中的卡通街区主视觉，品牌名称最醒目。游戏页将视觉重心转移到棋盘，不用装饰遮挡格子。桌面额外展示品牌海报区，手机只保留界面预览入口和游戏画面。

| 设计项 | 规范 |
| --- | --- |
| 主背景 | 薄荷绿 `#DCEFE4`，明亮但不刺眼 |
| 内容底色 | 奶油白 `#FFFAF0`，承载文本与操作 |
| 主按钮 | 珊瑚橙 `#F78462`，搭配橙棕色底部阴影 |
| 正文与轮廓 | 深蓝灰 `#263F47` |
| 奖励与提示 | 奶油黄 `#FFCF71` |
| 警察棋子 | 天空蓝 `#83B8D9` |
| 字体 | 优先本机圆润字体，回退苹方／微软雅黑；不依赖外部字体请求 |
| 字号 | 品牌 32–38px；页标题 18–27px；主按钮 15–21px；正文 12–15px |
| 圆角 | 按钮 15–18px、面板 20–29px、图标圆头线条；绝大多数可见组件采用圆角 |
| 间距 | 以 4px 为基础，常用 8／12／16／24px |
| 图标 | 统一 32×32 视框，深色描边、彩色填充，避免混用表情符号 |

## 二、页面方案

| 页面 | 核心内容 | 主操作 |
| --- | --- | --- |
| 启动加载 | 警徽 Logo、游戏名称、圆角进度条、健康游戏提示 | 演示加载后进入主菜单 |
| 主菜单 | 品牌、卡通街区、下一关信息、关卡进度 | 底部“开始游戏”；关卡、设置、我的各一步到达 |
| 游戏主界面 | 分数、步数、倒计时；6×6 棋盘；小队托盘 | 固定底栏：暂停／提示／重置；顶部返回 |
| 关卡选择 | 四列关卡网格、通关星级、当前关高亮、锁定图标 | 纵向滑动浏览；底部继续巡逻 |
| 胜利结算 | 警徽、三星、分数、步数、耗时 | 下一关、重新开始、分享、返回菜单 |
| 失败结算 | 小偷图标、低饱和星星、失败数据、鼓励文案 | 再试一次；避免惩罚性文案 |
| 设置 | 音效开关、音量滑块、触觉反馈、协议入口 | 底部返回；切换状态即时可见 |
| 个人中心 | 游客头像、通关数、星星、最高分、成就徽章 | 再来一局、巡逻地图 |
| 暂停弹层 | 局部遮罩、暂停文案 | 继续游戏／返回小镇 |
| 辅助弹层 | 玩法说明、协议版式、分享选择、清除确认 | 明确的主次按钮 |

## 三、触控与响应式

- 设计目标宽度为 360–480px，桌面预览框宽度为 414px。
- 所有按钮、开关、选择器触控高度至少 48px，开关视觉轨道小于热区。
- 6×6 棋盘格最小为 48px，窄屏不以整体缩放牺牲格子尺寸。
- 主菜单的开始按钮与导航、游戏底栏、各页主操作独立于中间滚动区，保持可触达。
- 短屏允许内容纵向滚动，底部操作区保持可见；不压扁主视觉或棋盘。
- 预留 `safe-area-inset-top`、`safe-area-inset-bottom`；正式宿主还需按胶囊按钮实际位置配置顶部留白。
- 保留浏览器缩放能力、键盘焦点样式和弹层焦点循环。

## 四、动效规范

| 交互 | 时长 | 视觉效果 |
| --- | --- | --- |
| 按钮按压 | 200ms | 下移 3px、轻微缩小、阴影收紧 |
| 页面切换 | 300ms | 淡入与上移 9px |
| 弹层出现 | 300ms | 轻微位移、透明度过渡 |
| 遮罩出现 | 200ms | 淡入 |
| 开关切换 | 200ms | 滑块位移与轨道变色 |
| 加载进度变化 | 400ms | 圆角进度条平滑增长 |

不使用持续闪烁或大范围循环动画。用户启用“减少动态效果”时关闭动画和过渡。启动页的计时仅演示加载流程，不代表真实资源进度。

## 五、未来对接建议

以下仅为设计约定，本次不实现：

- 微信／抖音分享：触发平台允许的原生分享入口；宿主返回结果前不显示“分享成功”，不以分享换奖励。
- 生命周期：离开前台时暂停倒计时，返回后由用户主动继续。
- 隐私与用户协议：正式文本须明确运营主体、联系方式、信息处理范围、第三方服务和未成年人保护。效果稿中的协议版式不等于正式合规文件。
- 游戏运行容器：HTML 展示稿不等于可发布的小程序或小游戏；正式发布须结合平台容器、域名配置和审核规则另行确认。

## 六、后续验收建议

本次不执行真机兼容性或用户研究，不声称满足未经实测的“零兼容问题”。

正式开发完成后，建议在 Android 与 iOS 的微信、抖音容器中覆盖 360／390／430／480px 的视口，检查安全区、字号、滚动、返回、暂停和分享。

邀请 5 名测试用户，各自完成“开始一局、暂停、重置、进入关卡、打开设置”五项任务。以“错误点击次数 ÷ 总点击次数”统计误触率，目标低于 5%；记录从听到明确任务到触发目标动作的耗时，目标不超过 3 秒。保留原始记录，不能以视觉预览代替可用性测试。
