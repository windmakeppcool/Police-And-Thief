# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This is a Cocos Creator 3.8.8 TypeScript project for the puzzle game “警察抓小偷”. Runtime code lives under `assets/GScript`; Cocos-managed scenes, prefabs, assets, and `.meta` files live under `assets` and should be kept in sync with the editor.

The project is split into Cocos Asset Bundles:

- `assets/Boost` is the boot bundle and contains `Main.scene` plus the `boost` component.
- `assets/GScript` is bundle `GScriptBN` and contains global TypeScript game infrastructure.
- `assets/Login` is bundle `LoginBN` and currently contains login audio resources.
- `assets/Game` is bundle `GameBN` and contains game prefabs, images, and JSON level data.

## Commands

```bash
# Install dependencies
npm install

# Run all Vitest tests
npm test

# Run pure game/platform tests (domain, rules, service, platform only)
npm run test:game

# Watch tests in pure game mode
npm run test:watch

# Run single test file
npx vitest run tests/game/path/to/test.test.ts

# Type-check pure game/platform code without Cocos
npm run typecheck:game

# Type-check full Cocos project (requires Cocos Creator)
npm run typecheck:cocos
```

**Testing setup**: Tests use Vitest with Node environment and `tests/**/*.test.ts` glob pattern. `test:game` excludes Cocos-specific code, keeping tests fast and platform-independent.

**TypeScript configs**: Two separate configs exist:
- `tsconfig.spec.json`: strict mode for pure game/platform code (used by `typecheck:game`)
- `tsconfig.json`: extends Cocos-generated config with non-strict mode (used by `typecheck:cocos`)

**Type-checking notes**: `typecheck:cocos` extends `./temp/tsconfig.cocos.json`, which is generated by Cocos Creator 3.8.8. If missing, open the project in Cocos Creator once and rerun.

## Startup flow

The startup scene is `assets/Boost/Main.scene`. Its `boost` component loads the `GScriptBN` bundle, dynamically adds the `GCtrl` component, and calls `GCtrl.init(...)` with the 2D canvas and a cleanup callback for the boost scene nodes.

`GCtrl` is the global runtime coordinator. During initialization it:

1. assigns itself to `globalThis.gCtrl`;
2. initializes `gCtrl.platform` from `PlatformFactory`;
3. initializes `UIManager` with the Canvas;
4. registers UI prefab URLs from `PrefabsCfg`;
5. initializes the login controller;
6. auto-runs login, then loads `GameBN` and opens `BoardBackgroundTiled` on success.

Most core systems assume `gCtrl` exists globally after bootstrap.

## Game architecture

Puzzle rules are pure TypeScript and must not import `cc`:

- `assets/GScript/game/domain/GameTypes.ts` defines coordinates, board sizes, rotations, piece types, placed pieces, level data, move results, and escape-path results.
- `assets/GScript/game/domain/PieceGeometry.ts` rotates shape cells and expands placed pieces into absolute board cells.
- `assets/GScript/game/domain/BoardOccupancy.ts` builds blocked-cell maps from buildings and placed police pieces.
- `assets/GScript/game/rules/PlacementValidator.ts` validates police placement against bounds, collisions, thief position, and inventory counts.
- `assets/GScript/game/rules/EscapePathFinder.ts` uses BFS to determine whether the thief can reach outside the board.
- `assets/GScript/game/rules/WinCondition.ts` converts escape-path results into win state.
- `assets/GScript/game/service/GameSession.ts` owns the current level state, placed police pieces, undo, and win checks.
- `assets/GScript/game/level/LevelExamples.ts` contains temporary development/test level data.
- `assets/GScript/game/level/LevelValidator.ts` validates shape catalogs and level data before runtime use.
- `assets/GScript/game/level/LevelSolver.ts` brute-force searches small levels to verify that at least one winning police placement sequence exists.

Cocos-facing glue lives separately:

- `assets/GScript/game/controller/GameController.ts` creates a `GameSession`, runs the example solver during `start()`, and bridges Cocos events to pure game logic.
- `assets/GScript/game/view/BoardGridView.ts` maps board coordinates to Cocos local positions and sizes board nodes.
- `assets/GScript/game/view/DebugBoardRenderer.ts` draws a temporary colored debug board using `Graphics` so Cocos Preview can show empty cells, police, buildings, and the thief without final art assets.
- `assets/GScript/game/view/BoardBackgroundTiled.ts` displays the current tiled board background on `EViewLayer.Scene`.

## Platform architecture

All platform-specific APIs should go through `assets/GScript/core/platform/PlatformAdapter.ts`. Current implementation includes:

- `PlatformAdapter.ts`: common interface for init, launch options, login, storage, ads, sharing, and event reporting.
- `WebPlatformAdapter.ts`: default web implementation using `localStorage` when available, otherwise memory storage.
- `PlatformFactory.ts`: currently returns the web adapter for all detected runtimes; add concrete WeChat/Douyin/Harmony adapters behind this factory later.

Do not call `wx.*`, `tt.*`, Harmony APIs, or browser-only APIs directly from game rules, services, controllers, or views.

## UI architecture

`UIManager` owns the Canvas UI layers. It creates one node per `EViewLayer` value (`Scene`, `UI`, `Guide`, `Anim`, `Transform`, `Loading`, `Modal`, `Toast`) and mounts opened UI prefabs into the layer declared by the UI component's static `viewLayer` field. If a component has no numeric `viewLayer`, it defaults to `EViewLayer.UI`.

Opening UI is class-based: call `gCtrl.ui.open(SomeComponent)`. The component class must be registered in `PrefabsCfg`, which maps class names to bundle paths via `BL(...)`. `UIManager.instantiate` resolves the component class name, finds its prefab in the configured bundle, instantiates it, and adds the component if missing.

`UIManager.open` creates a `ResLoader`, loads the UI prefab and any extra assets declared by a static `R(resLoader)` method on the UI class, and attaches a `DestroyHook` so those asset references are released when the UI node is destroyed.

## Resource architecture

`ResConst.BL(path, bundleName)` creates an `IBundleUrl` object used throughout the codebase. `registerBUrlByCfg(PrefabsCfg)` registers UI prefab URLs by class name before any UI is opened.

`ResManager` wraps Cocos `assetManager` bundle and asset loading with Promise APIs:

- `gCtrl.res.loadBundleAsync(bundleName)` loads an Asset Bundle.
- `gCtrl.res.loadAssetAsync(bUrl, type)` loads a typed asset from a bundle URL.

When adding new prefabs intended for `gCtrl.ui.open(...)`, update `assets/GScript/auto/PrefabCfg.ts` with the component class name as the key and the prefab path in its bundle as the value.

`assets/GScript/auto/JsonCfg.ts` currently exposes `JsonsCfg.level(key)` for JSON level resources in `GameBN` under `Jsons/level/{key}`.

## Notes for edits

- Preserve Cocos `.meta` files when moving or renaming assets—Cocos needs these to track asset references.
- Bundle names in code must match the bundle names in directory `.meta` files (`GScriptBN`, `LoginBN`, `GameBN`).
- **Strict separation**: Keep `game/domain`, `game/rules`, and `game/service` completely free of Cocos imports—this is required for `npm run test:game` to work.
- `npm install` currently reports 4 moderate vulnerabilities from the test tooling dependency tree; do not run `npm audit fix --force` without checking for breaking changes.
- Platform-specific APIs must go through `PlatformAdapter`—never call `wx.*`, `tt.*`, or browser APIs directly in game logic.
