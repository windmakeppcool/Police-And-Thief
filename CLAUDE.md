## Project overview

This is a Cocos Creator 3.8.8 TypeScript project. Runtime game code lives under `assets/GScript`, while Cocos-managed scenes, prefabs, assets, and `.meta` files live under `assets` and should be kept in sync with the editor.

The project is split into Cocos Asset Bundles:

- `assets/Boost` is the boot bundle and contains `Main.scene` plus the `boost` component.
- `assets/GScript` is bundle `GScriptBN` and contains global TypeScript game infrastructure.
- `assets/Login` is bundle `LoginBN` and currently contains login audio resources.
- `assets/Game` is bundle `GameBN` and contains game prefabs, images, and JSON level data.

## Commands

There are no npm scripts, test runner, or lint configuration in `package.json`. Use the Cocos Creator editor for normal development, preview, and builds.

Useful local checks:

```bash
# Inspect package metadata
npm pkg get

# TypeScript project config extends ./temp/tsconfig.cocos.json, which is generated by Cocos Creator.
# Run type checks only after opening/generating the project in Cocos so temp/tsconfig.cocos.json exists.

```

There is currently no single-test command because no automated test framework is configured.

## Startup flow

The startup scene is `assets/Boost/Main.scene`. Its `boost` component loads the `GScriptBN` bundle, dynamically adds the `GCtrl` component, and calls `GCtrl.init(...)` with the 2D canvas and a cleanup callback for the boost scene nodes.

`GCtrl` is the global runtime coordinator. During initialization it:

1. assigns itself to `globalThis.gCtrl`;
2. initializes `UIManager` with the Canvas;
3. registers UI prefab URLs from `PrefabsCfg`;
4. initializes the login controller;
5. auto-runs login, then loads `GameBN` and opens `BoardBackgroundTiled` on success.

Most core systems assume `gCtrl` exists globally after bootstrap.

## UI architecture

`UIManager` owns the Canvas UI layers. It creates one node per `EViewLayer` value (`Scene`, `UI`, `Guide`, `Anim`, `Transform`, `Loading`, `Modal`, `Toast`) and mounts opened UI prefabs into the layer declared by the UI component's static `viewLayer` field. If a component has no numeric `viewLayer`, it defaults to `EViewLayer.UI`.

Opening UI is class-based: call `gCtrl.ui.open(SomeComponent)`. The component class must be registered in `PrefabsCfg`, which maps class names to bundle paths via `BL(...)`. `UIManager.instantiate` resolves the component class name, finds its prefab in the configured bundle, instantiates it, and adds the component if missing.

`UIManager.open` creates a `ResLoader`, loads the UI prefab and any extra assets declared by a static `R(resLoader)` method on the UI class, and attaches a `DestroyHook` so those asset references are released when the UI node is destroyed.

## Resource architecture

`ResConst.BL(path, bundleName)` creates an `IBundleUrl` object used throughout the codebase. `registerBUrlByCfg(PrefabsCfg)` registers UI prefab URLs by class name before any UI is opened.

`ResManager` wraps Cocos `assetManager` bundle and asset loading with Promise APIs:

- `gCtrl.res.loadBundleAsync(bundleName)` loads an Asset Bundle.
- `gCtrl.res.loadAssetAsync(bUrl, type)` loads a typed asset from a bundle URL.

When adding new prefabs intended for `gCtrl.ui.open(...)`, update `assets/GScript/auto/PrefabCfg.ts` with the component class name as the key and the prefab path in its bundle as the value.

`assets/GScript/auto/JsonCfg.ts` currently exposes `JsonsCfg.level(key)` for JSON level resources in `GameBN` under `Jsons/level/{key}`.

## Current gameplay entry point

After login succeeds, `GCtrl` loads `GameBN` and opens `BoardBackgroundTiled`. `BoardBackgroundTiled` is a Cocos component mounted on `EViewLayer.Scene`; it configures a tiled sprite background sized from `gridSizeW`, `gridSizeH`, and `tilePixelSize`. Its `start()` resizes the node back to grid dimensions after `UIManager.open` initially applies the full-screen view size.

## Notes for edits

- Preserve Cocos `.meta` files when moving or renaming assets.
- Bundle names used in code must match the bundle names in the directory `.meta` files (`GScriptBN`, `LoginBN`, `GameBN`).
- `tsconfig.json` has `strict: false` and extends Cocos-generated `temp/tsconfig.cocos.json`; missing `temp` files usually mean the project has not been opened/generated by Cocos Creator in the current workspace.
